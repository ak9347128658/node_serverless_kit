# Architecture

nskit has two halves:

- **Deploy-time** (the `nskit` CLI and `node-serverless-kit/api`): turns `nskit.yml` into a deterministic zip plus Terraform JSON, and runs Terraform. It never calls cloud APIs directly.
- **Run-time** (`node-serverless-kit`, i.e. `src/index.ts` + `src/runtime/`): a zero-dependency library that esbuild bundles into every artifact. It translates each cloud's native events into one portable model and calls your handler.

## Deploy pipeline

```
nskit.yml (+ extends, providers:, stages:, CLI flags)
   │  config/loader.ts      merge layers, resolve ${env|opt|self|file}
   ▼
ServiceConfig (zod)         config/schema.ts - strict validation, camelCase (snake_case accepted)
   │  core/project.ts       pick Provider, default runtime, add <wf>-orchestrator functions
   ▼
Provider.validate()         capability / limit / runtime checks -> errors & warnings
   │  packaging/builder.ts  generated entry -> esbuild -> build/ -> artifact.zip
   ▼
.nskit/<provider>-<stage>/
   ├── entry/               nskit-entry.ts + nskit_manifest.json (generated, input to esbuild)
   ├── build/               bundled entry (+ .map), manifest, provider files, assets, node_modules (externals)
   ├── artifact.zip         deterministic (sorted entries, fixed timestamps)
   │  Provider.render()     providers/<cloud>.ts -> TerraformDoc
   ├── main.tf.json         Terraform JSON (no HCL templating)
   │  terraform init / apply   terraform/runner.ts
   ├── terraform.tfstate    (unless provider.state configures a backend)
   │  core/describe.ts      `terraform output` (nskit) + config
   └── deployment.json  ──► dashboard/ ──► .nskit/dashboard/index.html
```

Key properties:

- **Terraform JSON, not HCL.** Providers build plain JS objects through `TerraformDoc`, so there is no quoting or templating to get wrong. User strings are escaped (`${` → `$${`) unless written as `${tf:...}`.
- **Reproducible artifacts.** The zip is byte-identical for identical inputs. Unchanged code means an unchanged hash and no redeploy.
- **One directory per provider and stage.** Each has its own Terraform workspace and state, so `aws-dev` and `gcp-prod` never interfere.
- **The `nskit` output** (below) is the only thing `nskit info` and the dashboard read, which keeps them provider-agnostic.

## Bundling

`packaging/builder.ts::buildArtifact` runs four steps.

**1. Generated entry module.** For every deployment nskit writes `.nskit/<provider>-<stage>/entry/nskit-entry.ts`:

```ts
// Generated by node-serverless-kit. Do not edit - regenerate with `nskit package`.
import { installBundle } from "<package>/src/runtime/manifest.ts";
import manifest from "./nskit_manifest.json";

const pick = (mod, path) => path.reduce((value, key) => (value == null ? value : value[key]), mod);
const handlers = {
  "src/orders.createOrder": () => import("../../../src/orders.ts").then((m) => pick(m, ["createOrder"])),
  "src/orders.getOrder": () => import("../../../src/orders.ts").then((m) => pick(m, ["getOrder"])),
};

installBundle({ manifest, handlers });

export { handler } from "<package>/src/runtime/adapters/aws.ts";   // Provider.entryCode()
```

- The **manifest** (`nskit_manifest.json`) lists every function: handler reference, HTTP routes with CORS, timeout, memory and physical resource name, plus embedded workflow definitions.
- The **handler table** maps each handler reference to a lazy `import()`. A handler module is evaluated only when its function is first invoked, so one shared artifact can serve many functions (an Azure Function App, the embedded workflow orchestrator, ...) without paying for every module's top-level code on each cold start.
- The last line is the provider glue from `Provider.entryCode()`: it exports whatever the platform calls (`handler` for Lambda, `default` with `fetch`/`scheduled` for Workers, ...).

**2. esbuild.** The entry is bundled into one file in the provider's format (`Provider.bundle`: `cjs` or `esm`; platform `node`, `neutral` or `browser`; entry file name such as `index.js`). Settings: `bundle`, `keepNames`, `target` = `node<major>` of the function runtime (or `es2022` for isolates), `sourcemap: "linked"` without sources content, `minify` from `package.minify`, `tsconfig` from `package.tsconfig`, `external` = provider externals (e.g. `@aws-sdk/*` on AWS) + `package.external`, `define: {"process.env.NODE_ENV": "\"production\""}`. ESM output for Node gets a `createRequire` banner so bundled CommonJS dependencies can still `require()` built-ins. `package.esbuild` is merged last.

**The `node-serverless-kit` alias.** Imports of `node-serverless-kit` in your code are aliased to the package's own `src/index.ts`, and the generated entry imports the runtime from `src/runtime/*.ts`. User code and the dispatcher therefore share **one** copy of the runtime (one `HttpError` class, one installed bundle), and nothing from the CLI side (`commander`, `zod`, `esbuild`, ...) ever ends up in the artifact. This is why the npm package ships `src/`.

**3. Assets, provider files and dependencies.** `package.include` files are copied next to the bundle; `Provider.extraFiles()` adds platform files (`host.json`, `package.json`, `Dockerfile`, ...). For Node platforms a `package.json` with `"type": "module"` or `"commonjs"` (matching the bundle format) is written so the platform loads the bundle the same way as locally. `Provider.dependencies` and `package.external` are installed into `build/node_modules` with `npm install --omit=dev --os=linux --cpu=<x64|arm64> --libc=glibc`, unless the provider builds remotely (`Provider.remoteInstall`) or `--skip-install` is given.

**4. Deterministic zip.** Entries are sorted, timestamps are fixed and generated text uses LF line endings; no timestamps or absolute paths are written into generated files. The SHA-256 of `artifact.zip` drives `source_code_hash`-style arguments, so Terraform only updates functions when the bytes change.

### Artifact layout

```
artifact.zip
├── <entry file>(.map)      bundled code: index.js (aws, most Node clouds), or the provider's entry name
├── nskit_manifest.json     functions -> handler, routes, CORS, timeout, physical names; embedded workflows
├── package.json            module type (+ dependencies) for Node platforms
├── <provider files>        e.g. host.json (azure), Dockerfile / func.yaml (oracle)
├── <package.include assets>
└── node_modules/           only externals and provider dependencies
```

The exact entry file and extra files per cloud are listed on each [provider page](providers.md).

## Runtime flow

```
cloud platform
   │ native event + context
   ▼
generated entry: installBundle({manifest, handlers}) + provider glue
   ▼
runtime/adapters/<cloud>.ts
   │ native payload -> Event (HTTP / queue / topic / storage / schedule / __nskit envelope)
   │ native context -> Context (request id, deadline, memory, waitUntil)
   ▼
runtime/dispatch.ts  execute(event, context, functionName)
   │ resolve the function in the manifest (or $NSKIT_FUNCTION / $NSKIT_HANDLER)
   │ HTTP: route match -> pathParams, 405 with Allow, CORS preflight (204)
   │ lazy import of the handler module (cached), call fn(event, context), await
   │ await context.waitUntil() work where the platform has no native waitUntil
   │ HTTP: coerce the result -> HttpResponse, map HttpError / exceptions -> JSON errors, log the request
   │ other: return the result / rethrow for platform retries; BatchResult semantics
   ▼
adapter: HttpResponse / result -> native response
```

- **Cross-copy safety.** Brand checks use `Symbol.for` (`isHttpError`, `isBatchResult`, `isHttpResponse`), and runtime singletons (the installed bundle) live on `globalThis`, so even two loaded copies of the runtime (ESM + CJS builds in tests) agree.
- **Isolate-safe.** `src/index.ts` and `src/runtime/` have no dependencies and no `node:*` imports; `Buffer` and `process` are only used behind guards (`runtime/util.ts`). The same runtime runs on Node 18+ and in Cloudflare Workers.

**The `__nskit` envelope.** Payloads nskit itself produces are wrapped as `{"__nskit": "<schedule|workflow|invoke>", "data": ...}`: schedule inputs, workflow task inputs and `invoke()` calls. Adapters recognise the envelope (`runtime/envelope.ts::unwrapEnvelope`), so the handler sees the right `event.type` and `event.data` even on clouds where everything arrives as HTTP (GCP, IBM, DigitalOcean, Cloudflare, Oracle; shared logic in `runtime/adapters/httpfn.ts`). There, failures come back as JSON 500 `{"errorType", "cause"}` so native workflows can match errors by name.

**Embedded workflows.** On clouds without a native engine (or with `engine: embedded`), `core/project.ts` adds a `<workflow>-orchestrator` function whose handler is the built-in `runtime/workflow.ts::orchestrate`. It runs the state machine from the manifest and calls task handlers in-process through the same dispatcher.

### The `nskit` Terraform output

Every provider emits an output named `nskit`:

```json
{
  "functions": { "<name>": { "id": "...", "arn": "...", "url": "...", "base_url": "...", "console": "..." } },
  "workflows": { "<name>": { "id": "...", "console": "..." } },
  "endpoint": "https://..."
}
```

`arn`, `url`, `base_url` and `console` are optional. `core/describe.ts` combines it with the config into `deployment.json`.

## State handling

Local state in `.nskit/<provider>-<stage>/terraform.tfstate` is fine for one developer. For teams and CI, set `provider.state` to a remote backend (S3 + DynamoDB lock, GCS, `azurerm`, Terraform Cloud…). Don't commit `.nskit/`: nskit writes a `.gitignore` there.

## Third-party providers

A provider is a subclass of `Provider` from `node-serverless-kit/api`:

```ts
// nskit-provider-mycloud/index.ts
import { HTTP, SCHEDULE, Provider, type Capability, type EntryContext, type RenderContext, type TerraformDoc, ref } from "node-serverless-kit/api";

export default class MyCloudProvider extends Provider {
  readonly name = "mycloud";
  readonly displayName = "My Cloud Functions";
  override readonly tier = "experimental";
  readonly terraformSource = "acme/mycloud";
  override readonly terraformVersion = ">= 1.0";
  override readonly defaultRegion = "eu-1";
  override readonly capabilities = new Set<Capability>([HTTP, SCHEDULE]);
  override readonly runtimes = { nodejs22: "node22" };
  override readonly maxTimeout = 300;

  entryCode(_ctx: EntryContext): string {
    // Glue appended to the generated entry: export what the platform calls.
    return `export { handler } from "nskit-provider-mycloud/adapter";`;
  }

  renderResources(doc: TerraformDoc, ctx: RenderContext): void {
    const functions: Record<string, unknown> = {};
    for (const [name, fn] of ctx.functionItems()) {
      const res = doc.resource("mycloud_function", name, {
        name: ctx.physicalName(name),
        runtime: ctx.runtimeIdOf(fn),
        source_zip: "${path.module}/artifact.zip",
        source_hash: ctx.artifact.sha256,
        environment: ctx.environment(name, fn),
      });
      functions[name] = { id: ref(res, "id"), url: ref(res, "url") };
    }
    doc.output("nskit", { functions, workflows: {}, endpoint: null });
  }
}
```

The adapter module converts the native event into an `Event` (and `Context`), runs it through the runtime dispatcher (`execute`) and converts the result back into the native response; the built-in adapters in [`src/runtime/adapters/`](../src/runtime/adapters/) are the reference. It is bundled into the artifact, so it must follow the runtime rules: no dependencies, and isolate-safe if the platform is a V8 isolate. Import runtime classes from the bare `node-serverless-kit` specifier (which the bundler aliases to the bundled runtime), not from a deep path, so the adapter and your handlers share one runtime copy.

Register it without changing nskit:

```bash
npm install --save-dev nskit-provider-mycloud
NSKIT_PROVIDER_PLUGINS=nskit-provider-mycloud nskit deploy --provider mycloud
```

```ts
// or programmatically
import { Project, Deployer, registerProvider, loadProviderPlugins } from "node-serverless-kit/api";
import MyCloudProvider from "nskit-provider-mycloud";

registerProvider(MyCloudProvider);                         // instance, class or factory
await loadProviderPlugins(["nskit-provider-other"]);       // resolved from process.cwd()
const project = Project.load("nskit.yml", { provider: "mycloud" });
await new Deployer(project).deploy();
```

`loadProviderPlugins` resolves each package from the project directory and uses its `provider` export, else its default export (an instance, class or factory). Registered names are accepted by the config loader and listed by `nskit providers`. The full checklist for built-in providers is in [`deploy_docs/CONTRIBUTING.md`](../deploy_docs/CONTRIBUTING.md).

## Programmatic API

Everything the CLI does is available from `node-serverless-kit/api`:

```ts
import { Project, Deployer, LocalRunner, getProvider } from "node-serverless-kit/api";

const project = Project.load("nskit.yml", { stage: "prod", provider: "aws" });
const issues = project.validate();                          // Issue[] (level, message, where)
const deployer = new Deployer(project, (line) => console.log(line));
const { artifact, tfFile } = await deployer.package({ skipInstall: true });
const record = await deployer.deploy({ autoApprove: true }); // DeploymentRecord
```

Notable exports: `loadConfig`, `parseConfig`, `ConfigError`, the zod schemas (`ServiceConfigSchema`, ...), `Project`, `Deployer` (`package`, `plan`, `deploy`, `remove`, `refreshInfo`), `buildArtifact`, `Provider` and capability constants, `getProvider`, `allProviders`, `registerProvider`, `loadProviderPlugins`, `TerraformDoc`, `escape`, `ref`, `TerraformRunner`, `findBinary`, `compileAsl`, `LocalRunner`, `VERSION`.
